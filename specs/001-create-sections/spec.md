# Feature: Create sections
Status: Implemented; integration pending · Updated: 2026-10-03

## Problem and scope
Administrators cannot add workshop sections. Implement an admin-only creation API,
a named-section dialog and a persisted section catalog. Preserve existing identifiers,
artwork, routes and the user's header edits. Section editing/deletion, uploads and
new publication behavior are out of scope.

## Requirements and acceptance
- FR-001 / AC-001: Given an administrator, submitting a trimmed name of 1–120
  characters creates a section with a server-generated ID; it appears immediately
  in the catalog and after reload, and links to its workshop list.
- FR-002 / AC-002: Blank/overlong names and unknown request fields are rejected.
  The dialog prevents duplicate submissions while pending; failures retain input
  and allow retry; cancellation does not create a section.
- FR-003 / AC-003: Non-admin callers cannot create sections; reads remain public.
- FR-004 / AC-004: Existing section IDs are unchanged. Cards display artwork from
  each section's `headerSvgPath`, with a generic icon when no path is configured.
  Empty catalogs and workshop lists are useful.

## Decisions
Name only for this first creation flow. Existing numeric summary and SVG path
fields retain their contracts with server defaults; do not repurpose summary.
Names need not be unique; IDs are unique and generated by MongoDB's ObjectId.
No new package version is needed in the editor: its request is a Pick of the
published SectionDto's sectionTitle, and the response is the existing SectionDto.

## Constitution Check
Preserve boundaries and shared exports; use typed services, Material forms and
server admin guards. Test observable success, invalid input, failure and navigation.
Mocked persistence/auth checks do not certify live MongoDB or auth integration.
